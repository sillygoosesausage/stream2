# Final Submission — Model Information, Reproduction, and Disclosure

Inter-Uni Datathon Stream 2: Beijing Multi-Site Air Quality.
Team **tennis net sitters**. Metric: RMSE on 51,063 held-out station-hours.

This document covers required materials 5 (README / reproduction), 6 (final
model information) and the required disclosure. Material 1 (methodology) is
`reports/experiment_record.md`. Material 2 (source) is `src/`. Material 3 (the
prediction file) is named below. Material 4 (processed datasets) is fully
regenerable — see §4.

## 2. Final model information

All five components share the same data pipeline (§3) and the same
post-processing (§2.6). They differ in feature set, hyperparameters, and
averaging scheme.

### 2.1 Component A — `exp004_tuned_wspike` (weight 1/5)

- Feature set `best_v1`, **170 features**: raw measurements + tier C0 (lead
  covariates) + tier D (cross-station) + tier B (meteorology) + tier C lags and
  diffs. Excluded: tier A calendar, tier C rolling windows, tier F ratios,
  tier E null flags — each measured harmful.
- LightGBM, objective `regression`, metric `rmse`.
- `learning_rate` 0.022009077170577436, `num_leaves` 242,
  `min_data_in_leaf` 134, `feature_fraction` 0.6649900721373205,
  `bagging_fraction` 0.6542533236720767, `bagging_freq` 5,
  `lambda_l1` 4.714235909254678, `lambda_l2` 1.393978675022225.
- Sample weights `1 + 1.0 × y / mean(y)` (spike weighting).
- 5 seeds (1–5) averaged, fitted on all 360,954 training rows, 1847 rounds.
- Hyperparameters from Optuna, 30 trials — `experiments/tuning_best.json`.

### 2.2 Component B — `exp006_bagged15` (weight 1/5)

- Same feature set and hyperparameters as component A.
- 15 models, each on a random **60% subset of the columns**, top-8 features by
  gain always retained; predictions averaged.
- Generated by `src/submit_bagged.py`.

### 2.3 Component C — `exp002_best_v1` (weight 1/5)

- Same 170-feature set.
- LightGBM defaults: `learning_rate` 0.05, `num_leaves` 127, no sample weights,
  single seed.
- The untuned model, and the weakest standalone. It is also the most valuable
  member per unit of weight: equal fifths beat every weighting that reduced its
  share.

### 2.4 Component D — `exp012_tierG` (weight 1/5)

- Feature set `best_v3_leadmax`, **237 features** = `best_v1` + tier G
  (leads t+4..t+6, second-order boundary differences, acceleration, city-wide
  aggregates and anomalies for all pollutants, city spread, rolling-relative
  ratios).
- Component A's hyperparameters and spike weighting, 5 seeds, 650 rounds.
- **Scores +0.18 worse than component A on fold B** and improves the blend by
  0.058. Kept for decorrelation (error correlation 0.974).

### 2.5 Component E — `exp013_tierHcw` (weight 1/5)

- Feature set `best_v4_Hcw`, **195 features** = `best_v1` + mean/std/min/max
  over a 5-hour window **centred on the predicted hour** (t−1..t+3) for PM10,
  CO, NO2, WSPM, TEMP, plus the standardised position of t+1 within it.
- Component A's hyperparameters and spike weighting, 5 seeds, 1126 rounds.
- Neutral on fold B (+0.017, 95% CI [−0.075, +0.129]); adds 0.011 to the blend,
  which is inside leaderboard noise and should be read as "not worse."

### 2.6 Post-processing

Predictions are clipped to `[2.0, 999.0]`, the observed range of the training
target; the lower bound is the one that binds. **No other post-processing of any
kind is applied.** Smoothing, rescaling, global and per-stratum bias correction,
isotonic recalibration and spike expansion were all tested and all rejected —
every variant helped one validation fold and hurt the other (experiment record
§8.3).

## 3. Reproduction

### 3.1 Dependencies

    pip install -r requirements.txt

Key packages: `pandas`, `numpy`, `lightgbm`, `scikit-learn`, `pyarrow`,
`scipy`. `optuna` is needed only to re-run the hyperparameter search;
`xgboost` only to reproduce the negative diversity result. CatBoost is not used.

### 3.2 Required input files

    data/raw/train.csv
    data/raw/test.csv                (the corrected release; see §5.1)
    data/raw/sample_submission.csv

### 3.3 Execution order

```bash
# 1. The five components (each writes submissions/<exp-id>.csv, ~15 min each)
python -m src.submit tuned_wspike      --seeds 5 --exp-id exp004_tuned_wspike
python -m src.submit_bagged --bags 15 --frac 0.6 --exp-id exp006_bagged15
python -m src.submit best_v1           --seeds 1 --exp-id exp002_best_v1
python -m src.submit tuned_wspike_G    --seeds 5 --exp-id exp012_tierG
python -m src.submit tuned_wspike_Hcw  --seeds 5 --exp-id exp013_tierHcw

# 2. The final submitted file (seconds — pure arithmetic on the five CSVs)
python -m src.blend_csv \
    exp004_tuned_wspike:1 exp006_bagged15:1 exp002_best_v1:1 \
    exp012_tierG:1 exp013_tierHcw:1 \
    --out exp022_b5_GHcw
```

`submissions/exp022_b5_GHcw.csv` is the file that produced 18.54180.

### 3.4 Seeds and determinism

`src/config.py` sets `SEED = 42`. Each fit additionally sets `seed`,
`bagging_seed` and `feature_fraction_seed` to the seed index (1..N), so a
5-seed run uses seeds 1–5. Runs are reproducible given identical LightGBM and
data versions. Seed noise is large — fold B standard deviation 0.263 on a single
seed — so a single-seed reproduction will not land exactly on the reported
number; the 5-seed average will.

Round counts are calibrated by early stopping on fold B and scaled by
`len(train) / n_fold_B_train` ≈ ×1.40, since no validation split remains once
all data is used.

### 3.5 Validation

```bash
python -m src.ensemble fit <member> --seeds 5 --fold B   # cache fold predictions
python -m src.paired <candidate> tuned_wspike --fold B   # PAIRED comparison
python -m src.postproc tuned_wspike                      # post-processing sweep
python -m src.tracker show                               # local vs leaderboard
```

Use `src/paired.py` rather than differencing two RMSEs. Comparing independent
means gives a noise floor of ~0.4 RMSE on fold B; paired per-row differencing on
identical seeds, bootstrapped over day-long blocks, gives ±0.10 on correlated
models.

## 4. Processed datasets

Everything under `data/processed/` is regenerated from `data/raw/` by the code
and none of it is required as an input.

- The feature panel is built in-process by `features.build_panel_features()`
  (~60 s) — a complete station × hour grid spanning train and test together, so
  lags mean real elapsed hours and the first test hours receive correct history.
- `data/processed/preds/*__fold{A,B}.parquet` are cached per-seed validation
  predictions, so blending and seed-averaging questions are arithmetic rather
  than refits.
- `data/processed/stage1_*.parquet` belong to the two-stage experiment, a
  documented negative result that is not part of the final pipeline.

### 5.1 Dataset provenance — the 2026-09-06 correction

Mid-competition the organisers released a corrected dataset with the
`current_PM2_5` column removed from `train.csv` and `test.csv`, because for
consecutive hourly test rows that column at *t+1* reveals row *t*'s target.

**This project used the corrected files throughout.** The corrected release is
byte-identical to the files already in `data/raw/`:

| File | MD5 |
|---|---|
| `train.csv` | `31062b0e8bd99448375d72671bf950bb` |
| `test.csv` | `e4cdef2dfaf808b2da9aee5bc5d83e8c` |
| `sample_submission.csv` | `ca98dae9f962e0f597c77e2be21d9047` |

`cmp` reports no byte difference, and installing the corrected files over the
git-tracked originals produces an empty `git status data/raw/`. `train.csv`
carries `PM2_5_next_hour` (the target) and no other PM2.5 column; `test.csv`
carries no PM2.5 column at all. **No model was refitted and no reported result
is affected.**

This also explains a discrepancy noted from the start of the project: the
competition overview described a "Current PM2.5 concentration" field the data
did not contain. The overview described the *original* release. The
`leakage_guard` and `assert_test_computable` checks in `src/data.py` were built
to enforce, by inference from the data alone, exactly the constraint the
organisers later made explicit.

### 5.2 One disclosure that deserves emphasis

Blend membership was selected by submitting to the **public** leaderboard, not
by local validation, because local validation was measured to be incapable of
ranking blends — Spearman −0.564 (p = 0.090) across ten submitted blends
(experiment record §9.3, §9.6). Twelve blend variants were submitted in one
session for this purpose.

The final entry uses **equal weights** specifically to limit the resulting
exposure: there are no fitted parameters anywhere in the blend. But the
*membership* of the pool was chosen with leaderboard feedback, and that is a
form of selection the public score cannot itself validate. A reviewer should
read the 18.54180 as carrying more selection risk than the 18.78847 of the
single tuned model, which was chosen on local evidence alone.

### Known limitations

1. **Fold A is anti-correlated with the leaderboard** (Spearman −0.40) and is
   not used for selection. Its difficulty is most likely an artifact of
   training-set size (155k rows against fold B's 258k and the final fit's 361k)
   rather than a second opinion about the test period.
2. **Fold B has been consumed as a selection set** — roughly 25 feature
   decisions were made against it — and it is *negatively* correlated with the
   leaderboard on blends.
3. **Only two usable validation windows exist.** Rolling-origin validation with
   4–5 Sep–Feb windows would cut decision variance, but the data supports only
   three such windows and one (fold C, 52k training rows) is data-starved.
4. **The final fit trains through Aug 2016** — roughly 100k rows that appear in
   no validation fold.
5. **0.84% of rows carry 16.6% of squared error** — those whose t+1 PM10 was
   imputed rather than measured. Every attempt to exploit this made those rows
   *worse* (experiment record §8.5). It remains the largest identified and
   unexploited concentration of error.
6. **Blend membership was selected on the public leaderboard** (§5.2).
